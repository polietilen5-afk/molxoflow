Case study / desktop assistant

Carrier requests buried in group chats, turned into structured leads

A dispatcher follows dozens of chats to spot people who need a ride or a parcel delivered. The assistant reads the chats for them, extracts each request into clean fields and shows which route fits.

  • Desktop app
  • LLM extraction
  • Regex fallback

1

The problem

Requests arrive as free text in many chats, with typos and shorthand. Finding the relevant ones and comparing them with the timetable took the manager hours of scrolling and copy-pasting.

2

What we built

A desktop app that watches the chats, extracts type, route, date and volume with a language model (with a rule-based fallback), and scores every request against the carrier's routes.

3

The result

From hours of scrolling to a short list of ready matches. One place for every request, a confidence level on each and a reply template one click away.

How it works

Four steps from a chat line to a reply

  1. 1

    Read

    The app reads new messages from the manager's own chats on the same computer, nothing leaves the machine except the text sent for extraction.

  2. 2

    Extract

    A language model returns type, origin, destination, date and volume. If it is unavailable, a pattern-based parser takes over.

  3. 3

    Match

    Cities are normalised and compared with each active route: exact, nearby or reversed, plus service type and running days.

  4. 4

    Reply

    The manager sees a confidence level, picks a trip and gets a ready reply to send. Nothing is sent automatically.
